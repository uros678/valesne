[ ABOUT ]
valesne — Latin for "are you well?" (the answer: valeo, "I am well")
version {{.Version}}
config {{.Path}} (loaded {{.LoadedAt}})
A small monitor for hosts and services. It resolves hosts through DNS, pings them and checks their web pages, queries DNS servers directly, checks TLS certificates and (optionally) the Docker daemon and its containers. The last results of every check are drawn as small graphs on the STATUS page.
Single binary written in Go, the web pages are built in. Runs on Windows and Linux.
[ SETTINGS ]
Settings are edited in the config file above (TOML format, lines starting with # are comments). The program picks up changes by itself within a few seconds, no restart is needed (except for listen_port). Errors in the file are shown on the STATUS page; the program keeps running with the last valid configuration.
The sections below explain the settings with the examples of the default config (written on first start); they do not show your values (what is checked is on the STATUS page). Hosts, DNS servers and certificates are lists with one line per entry (mind the comma at the end of each line). The block form works too ([[targets]] with one key per line, for each entry), but not both forms for the same list. Blocks must come after the lists: a key = … line after a [[…]] header belongs to that block.

HOSTS · targets name · url · host · ok_status
One line per host in the targets = [ … ] list (or a [[targets]] block per host). Each host gets a ping (the name is resolved by the system resolver; when that fails, ping shows DNS: ...) and an HTTP check when url is set (by default a response of 200-399 = OK, see ok_status).
namename shown on the page (optional, defaults to host)
urlapplication address for the HTTP check (optional; no url = no HTTP check)
hostname or IP for the ping check (optional when url is set - taken from it)
ok_statusHTTP status codes that count as OK (optional, default 200-399), a list of codes and ranges, e.g. 200-399,401. A page behind a login often answers 401 or 403: add that code when you only want to know that the web server is up.
Default config:
targets = [
  { name = "Example",    url  = "https://example.com" },   # ping + HTTP
  { name = "Cloudflare", host = "1.1.1.1" },               # ping only
  # { name = "Behind a login", url = "https://intranet.example.com/app/", ok_status = "200-399,401" },
]
DNS SERVERS · dns_servers name · server · query
One line per DNS server in the dns_servers = [ … ] list (or a [[dns_servers]] block per server), queried directly (bypassing the system resolver). OK = answered (NOERROR/NXDOMAIN) · WARN = answered with an error (REFUSED, SERVFAIL …) · FAIL = no answer.
namename shown on the page (optional, defaults to server)
serverserver IP, optionally with a port (default 53), e.g. 10.0.0.1:53
queryname to ask for (optional, defaults to dns_query)
Default config:
dns_servers = [
  { name = "Cloudflare DNS", server = "1.1.1.1" },
  { name = "Quad9",          server = "9.9.9.9", query = "example.com" },   # own query
  # { name = "Internal DNS", server = "10.0.0.10", query = "intranet.company.local" },
]
CERTIFICATES · certs name · host · address
One line per TLS certificate in the certs = [ … ] list (or a [[certs]] block per certificate), e.g. to notice in time when certbot stops renewing. The certificate actually served on the address is checked, so a missing web server reload after a renewal is noticed too. OK = enough time left · WARN = less than 1/4 of the lifetime left, the renewal is overdue (certbot renews at about 1/3); at most 30 days before expiry, so a 1-year certificate warns at 30 days, not 99 · FAIL = fewer than 7 days left, or expired. Not reachable (connection refused, no TLS on the port) or not valid (hostname, chain, self-signed) is WARN with the error but never alerts: only the expiry does.
namename shown on the page (optional, defaults to host)
hostname on the certificate, used for SNI and verification, e.g. example.com (no https://, no port)
addresswhere to connect, host:port or IP:port (optional, defaults to host:443). Behind Cloudflare or another proxy set the origin here, e.g. 192.168.1.10:443, otherwise you see the proxy's certificate instead of your own.
Default config:
certs = [
  { name = "Example", host = "example.com" },
  # { name = "My site", host = "my-site.example", address = "192.168.1.10:443" },   # origin behind a proxy
]
DOCKER · [[docker]] name · endpoint · monitored
Each [[docker]] block is one Docker daemon on this server. valesne only sends read-only requests, but the user it runs as needs access to the Docker socket (member of the docker group, or root). Daemon: OK = answers · FAIL = not reachable. Container: OK = running (and healthy) · WAIT = health check starting · WARN = unhealthy or restarting · STOPPED = exited · FAIL = missing or dead. Every container on the daemon is shown; a STOPPED one counts as DOWN only when it is monitored (in the monitored list), otherwise it is just shown. Monitored containers are listed first on the status page, with [MONITORED] next to their status. The default config has this block turned off (docker_check = false); set it to true to use it.
namename shown on the page (optional, defaults to endpoint)
endpointunix:///var/run/docker.sock or tcp://host:2375 (optional, defaults to DOCKER_HOST when set, e.g. by docker-compose.yml, otherwise the unix socket)
monitoredthe containers that must be running: container name or compose service name, e.g. ["web", "db"] (optional); the others are only shown. Stopped or gone (docker compose down) is FAIL and alerts.
Default config:
[[docker]]
name = "Docker"
# endpoint  = "unix:///var/run/docker.sock"   # optional, see above
# monitored = ["web", "db"]                   # these must run (alert)
